# HealthClues Tester handoff

Double-click `App/tester.bat`, or have Antigravity run it as a foreground command and wait for its exit code. The first real run creates a dedicated Codex Tester conversation; later runs resume its recorded thread ID from `App/.tmp/healthclues-tester/session.json`. It does not choose `--last`, because unrelated Codex conversations exist on this machine. Each run re-reads the current project documents and source, so conversation memory never substitutes for current evidence.

Antigravity writes a short handoff to `App/.tmp/healthclues-tester/ANTIGRAVITY_HANDOFF.md` before calling the batch. Include changed paths, current isolated local demo URL/build, exact tests run and their output, known limitations, and the previous Tester run ID being addressed. Do not include secrets, real user data or instructions to access production. The runner snapshots the handoff for that run. A manual Tester run may omit the handoff; the review then starts from `CURRENT_STATE.md` and actual source.

After the batch exits **0**, Antigravity reads `App/reports/tester/LATEST.json`, checks `status: COMPLETE`, then reads the referenced `review` and `prompt` paths. `App/reports/tester/PROMPT_FOR_ANTIGRAVITY.md` is the stable convenience copy. A batch exit of **0** means the review file is complete, not that the game passed. `verdict` is `PASS`, `REWORK` or `BLOCKED`; only a fully evidenced local playable scope can be `PASS`. The pointer changes to `RUNNING` at the start and `ERROR` on a failed run, so an old `COMPLETE` result is not reused. On a nonzero exit, stop and resolve the Tester runtime issue. Each run also has a unique directory under `App/reports/tester/`.

Suggested one-time instruction to Antigravity: after each implementation round, write the handoff, call `App/tester.bat` synchronously, inspect the exit code and run ID, read the new prompt, fix actionable `REWORK` findings, then repeat. Stop on `PASS` or an external `BLOCKED` item; do not loop endlessly or invent verification. A file does not wake a desktop Antigravity conversation after its turn has already ended. This workflow assumes Antigravity remains in its task and waits for the batch command to return.

If a run is interrupted and `App/.tmp/healthclues-tester/run.lock` remains, inspect its PID and confirm no Tester or Codex process is still running before removing that lock. Never delete session state or earlier reports just to restart.

`tester.bat --check` verifies local files and the installed Codex CLI resume command without starting an AI review. The Tester invokes Codex with a read-only source sandbox. After independently verifying the loopback Owner Demo identity, it may create fresh synthetic local test accounts and progress for real end-to-end acceptance; existing demo accounts remain untouched. Source edits, production data, deployment, commit, push, real email and paid/live health inference are outside its task. All Tester evidence files and screenshots must stay under `D:\botly`. Browser and physical-device coverage must be marked `UNVERIFIED` when unavailable; older acceptance reports are context, not fresh PASS evidence.
